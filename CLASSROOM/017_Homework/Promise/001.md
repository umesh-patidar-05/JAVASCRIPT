# 1. Promise in JavaScript

## 1. What is a Promise?

A `Promise` is an object in JavaScript that represents the eventual completion or failure of an asynchronous operation.

In simple words, Promise ek aisa object hai jo hume future mein milne wale result ko represent karta hai. Result abhi available nahi hota, lekin future mein mil sakta hai ya error aa sakta hai.

**Example:**

Suppose we order food online.

1. We place an order.
2. The restaurant accepts the order.
3. Food is prepared.
4. Food is delivered.

When we place the order, we don't receive the food immediately. We have to wait.

Similarly, a Promise represents a result that may be available in the future.

## 2. Why do we use Promises?

We use Promises to handle asynchronous operations.

Common examples:

- Fetching data from an API.
- Reading files.
- Database operations.
- Making network requests.
- Performing tasks that take some time.

**Without Promises:** Handling multiple asynchronous operations using callbacks can become difficult.

**With Promises:** We can handle asynchronous operations in a cleaner and more manageable way.

## 3. Three States of a Promise

A Promise has three states:

| State | Meaning |
|---|---|
| Pending | Operation is still in progress. |
| Fulfilled | Operation completed successfully. |
| Rejected | Operation failed. |

**Important:**

- Initially, a Promise is in the `pending` state.
- It can become `fulfilled` or `rejected`.
- Once settled (fulfilled or rejected), its state cannot change again.

### Example: Promise States

```javascript
let promise = new Promise((resolve, reject) => {

    resolve("Task completed successfully");

});

console.log(promise);
```

**Output (conceptually):**

```text
Promise {<fulfilled>: "Task completed successfully"}
```

Here:
- `new Promise()` creates a Promise object.
- `resolve()` changes the Promise state to fulfilled.
- The result is `"Task completed successfully"`.

## 4. How to Create a Promise?

We create a Promise using the `Promise` constructor.

**Syntax:**

```javascript
let promise = new Promise((resolve, reject) => {

    // Asynchronous operation

});
```

A Promise constructor accepts a function called the **executor function**.

The executor function receives two arguments:

| Argument | Meaning |
|---|---|
| `resolve()` | Used when the operation is successful. |
| `reject()` | Used when the operation fails. |

### Example 1: Creating a fulfilled Promise

```javascript
let promise = new Promise((resolve, reject) => {

    resolve("Success!");

});

console.log(promise);
```

**Output:**

```text
Promise {<fulfilled>: "Success!"}
```

### Example 2: Creating a rejected Promise

```javascript
let promise = new Promise((resolve, reject) => {

    reject("Something went wrong!");

});

console.log(promise);
```

**Output (conceptually):**

```text
Promise {<rejected>: "Something went wrong!"}
```

**Note:** Directly rejecting a Promise without attaching a rejection handler may produce an unhandled rejection warning.

## 5. How to Handle a Promise?

We mainly use three methods to handle Promises:

| Method | Description |
|---|---|
| `.then()` | Handles a fulfilled Promise. |
| `.catch()` | Handles a rejected Promise. |
| `.finally()` | Executes after the Promise settles, whether fulfilled or rejected. |

### Example 1: then()

The `.then()` method executes when a Promise is fulfilled.

```javascript
let promise = new Promise((resolve, reject) => {

    resolve("Data received successfully");

});

promise.then((result) => {

    console.log(result);

});
```

**Output:**

```text
Data received successfully
```

### Example 2: catch()

The `.catch()` method handles a rejected Promise.

```javascript
let promise = new Promise((resolve, reject) => {

    reject("Network Error");

});

promise.catch((error) => {

    console.log(error);

});
```

**Output:**

```text
Network Error
```

### Example 3: finally()

The `.finally()` method executes after a Promise settles.

It executes whether the Promise is fulfilled or rejected.

```javascript
let promise = new Promise((resolve, reject) => {

    resolve("Task completed");

});

promise
    .then((result) => {
        console.log(result);
    })
    .catch((error) => {
        console.log(error);
    })
    .finally(() => {
        console.log("Process finished");
    });
```

**Output:**

```text
Task completed
Process finished
```

**Real-life use:** We can use `finally()` to hide a loading spinner after an API request finishes, whether it succeeds or fails.

## 6. Promise with setTimeout()

We can use Promises with `setTimeout()` to simulate asynchronous operations.

```javascript
let promise = new Promise((resolve, reject) => {

    setTimeout(() => {

        resolve("Data loaded successfully");

    }, 2000);

});

promise.then((result) => {

    console.log(result);

});
```

**Output after approximately 2 seconds:**

```text
Data loaded successfully
```

**Explanation:**

1. A Promise is created.
2. `setTimeout()` waits approximately 2 seconds.
3. `resolve()` fulfills the Promise.
4. `.then()` receives the result.
5. The message is printed.

## 7. Important Points About Promises

- A Promise represents the future result of an asynchronous operation.
- A Promise has three states: pending, fulfilled and rejected.
- `resolve()` is used for successful completion.
- `reject()` is used for failure.
- `.then()` handles fulfillment.
- `.catch()` handles rejection.
- `.finally()` executes after settlement.
- A settled Promise cannot change its state again.

# 2. Promise Chaining in JavaScript

## 1. What is Promise Chaining?

Promise chaining means connecting multiple `.then()` methods together to execute asynchronous operations one after another.

The result returned by one `.then()` can be passed to the next `.then()`.

**In simple words:** Jab ek asynchronous task complete hone ke baad doosra task execute karna ho, aur doosre ke baad teesra, tab hum Promise Chaining use karte hain.

## 2. Why do we use Promise Chaining?

We use Promise Chaining when:

- One task depends on the result of another task.
- We need to execute multiple asynchronous operations in sequence.
- We want to avoid deeply nested callbacks.
- We want to write cleaner asynchronous code.

**Real-life example:**

Suppose a shopping website performs these operations:

1. Get user details.
2. Get user's orders.
3. Get payment details.

The second task depends on the first task, and the third task depends on the second task.

We can use Promise Chaining for this.

## 3. Syntax of Promise Chaining

```javascript
promise
    .then((result) => {

        return anotherPromise;

    })
    .then((result) => {

        return anotherPromise;

    })
    .then((result) => {

        console.log(result);

    })
    .catch((error) => {

        console.log(error);

    });
```

**Important:** Always remember to return a value or Promise when the next `.then()` needs its result.

## 4. Examples of Promise Chaining

### Example 1: Simple Promise Chaining

```javascript
let promise = new Promise((resolve, reject) => {

    resolve(10);

});

promise
    .then((result) => {

        console.log(result);

        return result * 2;

    })
    .then((result) => {

        console.log(result);

        return result * 3;

    })
    .then((result) => {

        console.log(result);

    });
```

**Output:**

```text
10
20
60
```

**Explanation:**

1. Initially, the Promise resolves with `10`.
2. First `.then()` receives `10`.
3. It returns `10 * 2`, which is `20`.
4. Second `.then()` receives `20`.
5. It returns `20 * 3`, which is `60`.
6. Third `.then()` receives `60`.

**Remember:** The value returned by one `.then()` becomes the input of the next `.then()`.

### Example 2: Promise Chaining with setTimeout()

```javascript
let promise = new Promise((resolve, reject) => {

    setTimeout(() => {

        resolve("User found");

    }, 1000);

});

promise
    .then((result) => {

        console.log(result);

        return new Promise((resolve) => {

            setTimeout(() => {

                resolve("Orders found");

            }, 1000);

        });

    })
    .then((result) => {

        console.log(result);

        return new Promise((resolve) => {

            setTimeout(() => {

                resolve("Payment completed");

            }, 1000);

        });

    })
    .then((result) => {

        console.log(result);

    })
    .catch((error) => {

        console.log(error);

    });
```

**Output:**

```text
User found
Orders found
Payment completed
```

**Execution time:** Approximately 3 seconds.

**Explanation:**

1. First Promise takes approximately 1 second and returns `"User found"`.
2. First `.then()` receives that value and returns another Promise.
3. Second Promise takes approximately 1 second and returns `"Orders found"`.
4. Second `.then()` returns another Promise.
5. Third Promise takes approximately 1 second and returns `"Payment completed"`.

Each task waits for the previous Promise to complete.

### Example 3: Error Handling in Promise Chaining

```javascript
let promise = new Promise((resolve, reject) => {

    resolve("Step 1 completed");

});

promise
    .then((result) => {

        console.log(result);

        throw new Error("Something went wrong");

    })
    .then((result) => {

        console.log("Step 2 completed");

    })
    .catch((error) => {

        console.log(error.message);

    });
```

**Output:**

```text
Step 1 completed
Something went wrong
```

**Explanation:**

1. First `.then()` executes successfully.
2. An error is thrown inside it.
3. The next `.then()` is skipped.
4. `.catch()` handles the error.

**Important:** A rejected Promise or an error thrown inside a `.then()` skips the remaining fulfillment handlers until a rejection handler is found.

## 5. How Promise Chaining Works Internally

```text
Original Promise
       |
       ↓
    then()
       |
       ↓
 Returns a value/Promise
       |
       ↓
    then()
       |
       ↓
 Returns a value/Promise
       |
       ↓
    then()
       |
       ↓
    Final Result
```

**Important Concept:**

Every `.then()` returns a new Promise.

That is why we can connect multiple `.then()` methods together.

# 3. Drawbacks of Promise Chaining

Promise Chaining is better than deeply nested callbacks, but it also has some limitations.

## 1. Long Chains Become Difficult to Read

When we have many asynchronous operations, the chain can become very long.

```javascript
getUser()
    .then((user) => getOrders(user.id))
    .then((orders) => getPayment(orders[0].id))
    .then((payment) => getAddress(payment.id))
    .then((address) => getDelivery(address.id))
    .then((result) => console.log(result))
    .catch((error) => console.log(error));
```

**Drawback:**

- Long chains can become difficult to understand.
- Debugging can become challenging.
- Maintaining large chains can be difficult.

## 2. Error Handling Can Be Tricky

If we do not handle errors properly, an error may propagate through the chain.

```javascript
getUser()
    .then((user) => {

        return getOrders(user.id);

    })
    .then((orders) => {

        return getPayment(orders);

    })
    .catch((error) => {

        console.log(error);

    });
```

**Drawback:**

A single `.catch()` at the end handles errors from the previous chain, but sometimes we need different error-handling logic for different operations.

## 3. Forgetting return

One common mistake is forgetting to return a Promise or value from `.then()`.

**Incorrect Example:**

```javascript
Promise.resolve(10)
    .then((result) => {

        result * 2;

    })
    .then((result) => {

        console.log(result);

    });
```

**Output:**

```text
undefined
```

**Why?**

Because the first `.then()` does not return anything.

In JavaScript, a function without a return statement returns `undefined`.

**Correct Example:**

```javascript
Promise.resolve(10)
    .then((result) => {

        return result * 2;

    })
    .then((result) => {

        console.log(result);

    });
```

**Output:**

```text
20
```

## 4. Sequential Execution Can Take More Time

When operations are independent, chaining them makes them execute one after another.

```javascript
getUser()
    .then((user) => {

        return getProducts();

    })
    .then((products) => {

        return getOrders();

    });
```

If each operation takes 2 seconds, the total time can be approximately 6 seconds.

**Better Approach:**

If tasks are independent, we can use `Promise.all()` to execute them concurrently.

```javascript
Promise.all([
    getUser(),
    getProducts(),
    getOrders()
])
.then((results) => {

    console.log(results);

})
.catch((error) => {

    console.log(error);

});
```

If all three operations take approximately 2 seconds, the total time can be approximately 2 seconds.

**Important:** Promise chaining is not always slow. It is useful when one task depends on the result of another task. For independent tasks, concurrent execution is often better.

# 4. Difference Between Promise and Promise Chaining

| Promise | Promise Chaining |
|---|---|
| Represents an asynchronous operation's future result. | Connects multiple Promise operations. |
| Can handle one asynchronous operation. | Helps manage multiple dependent operations. |
| Uses methods like `.then()`, `.catch()` and `.finally()`. | Uses multiple connected `.then()` methods. |
| Example: `promise.then()` | Example: `promise.then().then().then()` |

---

# 5. Promise vs Callback

| Callback | Promise |
|---|---|
| A function passed as an argument to another function. | An object representing a future result. |
| Can lead to callback hell when deeply nested. | Provides chaining to organize asynchronous code. |
| Error handling may require separate conventions. | Provides `.catch()` for rejection handling. |
| Can be difficult to maintain when nested. | Generally easier to organize and maintain. |

# 6. Important Interview Questions

### Q1. What is a Promise in JavaScript?

A Promise is an object that represents the eventual completion or failure of an asynchronous operation.

### Q2. What are the three states of a Promise?

- Pending
- Fulfilled
- Rejected

### Q3. What is the use of resolve() and reject()?

- `resolve()` fulfills a Promise with a value.
- `reject()` rejects a Promise with a reason.

### Q4. What is Promise Chaining?

Promise Chaining is a technique of connecting multiple `.then()` methods to execute asynchronous operations in sequence.

### Q5. Does then() return a Promise?

Yes. Every call to `.then()` returns a new Promise.

### Q6. What happens if we forget to return a value inside then()?

The next `.then()` receives `undefined`, unless the callback returns something else implicitly.

### Q7. What is the difference between then() and catch()?

- `.then()` handles fulfillment.
- `.catch()` handles rejection.

### Q8. What is the purpose of finally()?

`finally()` executes after a Promise settles, regardless of whether it is fulfilled or rejected.

### Q9. Can we use multiple catch() methods in Promise Chaining?

Yes. We can use multiple `.catch()` methods to handle errors at different stages.

### Q10. What are the drawbacks of Promise Chaining?

- Long chains can become difficult to read.
- Error handling can become complicated.
- Forgetting `return` can cause unexpected results.
- Sequential execution can take more time when operations are independent.

### Q11. How can we improve Promise Chaining?

We can use `async/await` to write asynchronous code in a cleaner and more readable way.
